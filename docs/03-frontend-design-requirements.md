# 前端界面与样式设计要求

> 所属项目：个人日程系统  
> 视觉方向：温暖的安静手账  
> 技术依据：[步骤二：确认技术栈](./02-tech-stack.md)  
> 范围依据：[步骤一：明确第一版范围](./01-product-scope.md)  
> 文档状态：设计基线 + 当前实现说明  
> 更新日期：2026-11-20

> 实现说明（2026-11-20）：当前实现已包含登录页、注册页、多账号数据隔离、Tailwind CSS v4 和自动来源暂存区。本文档的视觉与交互基线仍然有效；涉及“免登录 / 单用户”的描述以 [登录与认证](./05-authentication.md) 和 README 为准。

## 1. 文档目的

本文档定义个人日程系统第一版的前端界面结构、视觉样式、交互方式和验收要求，作为 Vue 页面、组件、FullCalendar 主题和响应式实现的统一依据。

当前界面面向已登录的多账号用户，登录页、注册页和自动来源暂存区已实现；提醒、重复日程、标签和第三方日历导入仍未实现，界面不展示其入口。

## 2. 设计原则

### 2.1 时间优先

日历是页面主角。品牌说明、统计信息和辅助操作都应让位于日期与日程内容，不使用传统后台首页的指标卡片布局。

### 2.2 温和但有秩序

视觉借鉴个人手账的纸张色、留白、细线和克制的手写感，但不直接模拟真实纸张、胶带、贴纸或手绘涂鸦。界面需要长期使用仍清晰、稳定、不过度可爱。

### 2.3 三类日程一眼可辨

工作、外出、私人时间通过颜色、中文文字和不同展示位置共同区分，不能只依赖颜色。分类色用于表达时间类型，不表达优先级或好坏。

### 2.4 手动录入简单直接

创建和编辑表单优先展示标题、分类和时间。地点、描述和状态属于补充信息，可以在同一表单中折叠展示，不额外制造复杂的快速创建与高级创建两套流程。

### 2.5 安静反馈

操作反馈及时、明确但不过度打断。常用操作用内联加载和轻量提示，删除等不可逆操作使用确认弹窗。

## 3. 视觉概念

### 3.1 整体气质

- 背景像一张温暖、干净、没有明显纹理的日程纸
- 信息层级依靠字号、留白和线条建立
- 内容表面接近纸白，不使用大面积纯白
- 正文使用清晰的无衬线字体，月份和日期标题可以使用克制的衬线字体
- 圆角适中，按钮和卡片不呈现明显的玻璃、渐变或拟物材质
- 动效柔和、短促，只帮助用户理解界面状态变化

### 3.2 避免的视觉做法

- 不使用高饱和霓虹色或荧光色
- 不让阴影覆盖整个页面，只有抽屉、弹窗和浮层使用轻阴影
- 不使用大面积纸张纹理、横线纸背景或手写字体承载正文
- 不使用巨大欢迎语占据日历顶部
- 不把三类日程做成红、黄、绿的状态灯
- 不使用装饰性插画替代真实的加载、空数据和错误状态

## 4. 色彩系统

### 4.1 基础颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#F4F0E7` | 页面最底层暖纸背景 |
| `--color-surface` | `#FFFDF8` | 日历、侧栏、面板背景 |
| `--color-surface-raised` | `#FFFBF2` | 弹窗、浮层和抬高表面 |
| `--color-ink` | `#25231F` | 标题和主要文字 |
| `--color-ink-secondary` | `#5F5A51` | 次级文字 |
| `--color-ink-muted` | `#837C70` | 时间、占位符和辅助说明 |
| `--color-line` | `#DFD7C8` | 网格线、分隔线和边框 |
| `--color-line-strong` | `#C8BEAD` | 需要强调的边界 |
| `--color-focus` | `#2F6F88` | 键盘焦点环和主要交互状态 |
| `--color-danger` | `#A6473F` | 删除、错误和危险操作 |
| `--color-success` | `#52705B` | 保存成功等非分类反馈 |

### 4.2 分类颜色

| 分类 | 主色 Token | 主色 | 柔和背景 | 辅助文字 |
| --- | --- | --- | --- | --- |
| 工作 | `--category-work` | `#356E84` | `#E7EFF2` | 青墨蓝 |
| 外出 | `--category-outing` | `#BC6745` | `#F6E8E0` | 陶土橙 |
| 私人时间 | `--category-private` | `#75608A` | `#EEE9F2` | 暮光紫 |

使用规则：

- 日程卡片主体使用分类柔和背景，左侧使用 3px 分类主色
- 分类文字、圆点和图标使用分类主色
- 分类主色不能直接作为大段正文颜色
- 日程密集区域使用“一字符分类标记”：`工`、`外`、`私`
- 日程详情、编辑表单、筛选器和今日议程展示完整分类名称
- 颜色与文字不满足对比要求时，以文字可读性优先

### 4.3 状态样式

| 状态 | 展示方式 |
| --- | --- |
| 待进行 | 不增加多余徽标，保持正常视觉权重 |
| 已完成 | 标题前显示勾选图标，文字使用次级色 |
| 已取消 | 标题增加删除线并降低对比度，不隐藏日程 |

状态颜色使用中性色或成功色，不能覆盖分类色。紧凑日历卡片可以只显示状态图标，完整状态文字放在详情和编辑表单中。

## 5. 字体与排版

### 5.1 字体

```css
--font-sans: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-display: "Noto Serif SC", "Songti SC", "STSong", serif;
```

- 正文、表单、按钮和日程标题使用 `--font-sans`
- 月份标题、大日期和手账感标题使用 `--font-display`
- 数字时间和日期使用等宽数字特性 `font-variant-numeric: tabular-nums`
- 不依赖在线字体加载；系统字体不可用时应正常回退

### 5.2 字号与字重

| 场景 | 建议字号 | 字重 |
| --- | --- | --- |
| 页面主日期或月份 | 28～32px | 600 |
| 面板标题 | 20px | 600 |
| 日程详情标题 | 22px | 600 |
| 按钮和标签 | 14px | 500 |
| 正文与表单 | 14～15px | 400 |
| 日程卡片标题 | 13～14px | 500 |
| 时间、辅助信息 | 12～13px | 400 |
| 微标签 | 11～12px | 500 |

正文行高建议为 1.5～1.7。标题行高建议为 1.25～1.4。页面不应使用低于 11px 的文字。

## 6. 空间、形状与动效

### 6.1 间距

统一使用 4px 基础网格：

```text
4, 8, 12, 16, 24, 32, 48
```

- 紧凑图标与文字之间使用 4～8px
- 表单项之间使用 16～20px
- 面板内边距使用 20～24px
- 页面主要区域之间使用 20～24px
- 大区块之间使用 32～48px

### 6.2 圆角与边框

- 输入框、按钮：8px
- 日程卡片和内容卡片：10～12px
- 弹窗和抽屉：14～16px
- 分类筛选器和状态徽标：999px 胶囊
- 常规边框：1px `--color-line`
- 选中或焦点边框：1～2px `--color-focus`

### 6.3 阴影

- 日历主体不添加外阴影
- 日程卡片默认不使用阴影
- 选中日程可以使用分类柔和色或轻微背景变化
- 抽屉、弹窗和搜索浮层使用低透明度暖黑色阴影
- 不使用高扩散、深黑色的悬浮阴影

### 6.4 动效

- 抽屉打开、关闭：180～220ms
- 弹窗、浮层出现：140～180ms
- 悬停和按钮状态：100～150ms
- 只对透明度和位移做动画
- 遵循 `prefers-reduced-motion: reduce`，关闭非必要动画

## 7. 信息架构

日历主页是核心页面，日程详情、创建、编辑和搜索均作为面板、抽屉或浮层出现；登录页和注册页是独立的公开路由，不单独提供设置页。

页面区域：

1. 顶部工具栏
2. 左侧日历与分类区域
3. 中央日历画布
4. 右侧今日议程/日程详情/编辑面板
5. 搜索浮层
6. 删除确认弹窗

## 8. 响应式布局

### 8.1 桌面端：宽度大于等于 1280px

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 个人日程   2026 年 11 月   ‹ 今天 ›   [搜索]   [周][月]   [+ 新建] │
├────────────────┬──────────────────────────────────┬─────────────────┤
│ 小型月历        │                                  │ 今日安排          │
│                │                                  │ 09:00 项目周会    │
│ 工作  2         │            日历画布               │ 16:00 听音乐      │
│ 外出  1         │                                  │ 20:00 自主学习    │
│ 私人时间  3     │                                  │                 │
└────────────────┴──────────────────────────────────┴─────────────────┘
```

布局尺寸建议：

- 顶部工具栏高度：68～72px
- 左侧栏宽度：220～232px
- 右侧面板宽度：336～360px
- 页面主体高度：占满剩余视口，不产生整页滚动
- 日历画布内部滚动，左右区域保持固定

桌面端默认使用周视图。月视图用于查看整体分布，日视图用于查看一天的详细时间安排。

### 8.2 平板和中窄桌面：768～1279px

- 左侧栏默认收起，通过工具栏按钮打开
- 分类筛选以顶部横向胶囊或浮层形式提供
- 右侧详情和编辑使用覆盖式抽屉
- 日历画布占据主要宽度
- 顶部工具栏保留日期、视图切换、搜索和新建

### 8.3 移动端：小于 768px

```text
┌───────────────────────────┐
│ 11 月 4 日 星期三      [月] │
│ 今天 · 3 项安排              │
│                           │
│ 09:00  工  项目周会          │
│         工作 · 线上          │
│                           │
│ 16:00  私  听一小时音乐       │
│         私人时间             │
│                           │
│ 20:00  私  自主学习           │
│         私人时间             │
│                    [+ 新建]│
└───────────────────────────┘
```

- 移动端默认显示今日议程，而不是周视图
- 顶部提供日期导航和月视图入口
- 新建使用醒目的悬浮按钮或固定底部按钮
- 创建和编辑使用底部抽屉
- 日程详情使用底部抽屉，避免跳转页面
- 支持安全区域 `env(safe-area-inset-bottom)`
- 可点击控件最小高度为 44px
- 页面宽度为 320px 时不能出现横向溢出

## 9. 顶部工具栏

顶部工具栏包含：

- 产品名称“个人日程”
- 当前月份或日期标题
- 上一个周期、下一个周期、今天
- 视图切换：月、周、日
- 搜索入口
- 新建日程按钮

交互要求：

- “今天”始终可以一键回到当天
- 当前视图使用实心或深浅变化明确选中
- 新建按钮是最高视觉优先级的主操作
- 搜索框展开后自动聚焦，按 `Esc` 收起
- 桌面端可支持快捷键：
  - `N`：新建日程
  - `T`：回到今天
  - `/`：聚焦搜索
  - `Esc`：关闭浮层或抽屉
- 快捷键在输入框内编辑时不触发

## 10. 左侧区域

### 10.1 小型月历

- 用于总览月份和快速跳转日期
- 当前日期有圆形或柔和背景高亮
- 有日程的日期显示 1～3 个小圆点
- 点击日期后中央日历跳转到对应日期
- 不显示完整日程标题，避免视觉拥挤

### 10.2 分类筛选

三类筛选始终显示完整名称：

- 工作
- 外出
- 私人时间

每项包含分类色圆点、名称和当前计数。点击可以启用或禁用对应分类。

要求：

- 支持同时选择多个分类
- 全部未选择或“显示全部”时展示所有日程
- 禁用状态降低透明度，但仍能辨认
- 第一版不持久化筛选状态，刷新页面后恢复为显示全部分类
- 不能只显示无文字色块

### 10.3 其他筛选

状态筛选和时间范围筛选放在“更多筛选”区域，避免左侧栏长期拥挤。状态包括：

- 待进行
- 已完成
- 已取消

## 11. 中央日历画布

### 11.1 FullCalendar 基础设置

- 使用 `zh-cn` 语言包
- 一周从星期一开始
- 使用 24 小时制时间
- 显示当前时间指示线
- 月、周、日视图都使用同一套字体、边框和分类颜色
- 普通日程支持点击打开详情
- 空白日期或时间格支持点击创建
- MVP 不开启拖拽和缩放修改时间

### 11.2 视觉定制

- FullCalendar 外层背景透明，日历内容使用 `--color-surface`
- 网格线使用 `--color-line`
- 日期标题使用正文无衬线字体，月份标题使用衬线标题字体
- 今天使用轻微暖色背景或日期下方的分类中性强调
- 非当前月日期日期降低文字对比度
- 周视图和日视图的整点线比半小时线更明显
- 当前时间线使用低饱和红色或暖色，不覆盖日程文字
- 空日期不添加重复说明文字

### 11.3 日程数量

- 月视图每个日期默认最多显示 2～3 条紧凑日程，剩余显示“还有 N 项”
- 周视图和日视图根据时长显示完整或截短标题
- 时间过短的日程保留最小可点击高度
- 标题过长时省略，完整标题在详情和悬停提示中展示
- 同一天存在多个分类时，继续保持各自分类色

## 12. 日程卡片

### 12.1 常规样式

日程卡片包含可用的以下信息：

- 一字符分类标记或完整分类名
- 开始时间
- 标题
- 地点摘要
- 状态图标

视觉规则：

- 背景使用分类柔和背景
- 左侧或顶部使用分类主色标识
- 标题文字使用 `--color-ink`
- 时间使用 `--color-ink-muted`
- 圆角 8～10px
- 内边距 6～10px
- 卡片之间保留 3～4px 间隔
- 悬停时轻微提高表面亮度或加深边框，不使用明显放大

### 12.2 月视图紧凑卡片

```text
▎工 09:00 项目周会
▎私 16:00 听一小时音乐
```

空间不足时优先保留分类标记、时间和标题。月份格中最多展示 2～3 条。

### 12.3 周/日视图时间块

```text
▎ 私人时间
  听一小时音乐
  16:00–17:00
```

短日程只显示标题，较长日程可以展示地点或描述摘要。

### 12.4 全天和跨天

- 全天日程显示在时间网格顶部的全天区域
- 全天日程使用完整日期，不显示具体时刻
- 跨天日程在涉及的日期中保持同一标题和分类色
- 全天日程不参与普通时间块的垂直布局
- 后端全天日期按首尾日期都包含处理，前端展示时不能产生多一天或少一天

## 13. 右侧议程与详情面板

### 13.1 默认状态

未选择日程时，右侧显示“今日安排”：

- 今天的日期和星期
- 当天日程数量
- 按开始时间排序的日程列表
- 没有日程时显示空状态和新建入口

### 13.2 日程详情

点击日程后显示：

- 标题
- 分类
- 状态
- 日期
- 时间范围
- 地点
- 描述
- 编辑和删除操作

布局要求：

- 标题和分类在顶部形成第一视觉层级
- 时间和地点使用图标或清晰标签
- 描述保留换行
- 删除按钮使用低强调、危险色文字，不放在主按钮旁
- 创建时间和更新时间可以作为弱化元信息展示

### 13.3 操作

- “编辑”切换为编辑表单
- “删除”打开确认弹窗
- 取消编辑时，如果存在修改，需要提示是否放弃
- 面板关闭后回到今日安排
- 移动端使用可向下拖动关闭的底部抽屉

## 14. 创建与编辑表单

### 14.1 表单结构

表单按以下顺序展示：

1. 标题
2. 分类
3. 开始日期和时间
4. 结束日期和时间
5. 全天开关
6. 地点
7. 状态
8. 描述

标题输入框自动聚焦。分类使用三个大尺寸单选胶囊或卡片：

```text
[ 工作 ]   [ 外出 ]   [ 私人时间 ]
```

分类没有默认值，用户必须主动选择。选择后使用分类色边框和柔和背景强调，不使用只改变颜色的小圆点。

### 14.2 默认值

- 从日程空白时间格创建：使用点击的日期和对应时间作为开始时间，默认持续 1 小时
- 从月视图日期创建：默认从当天 09:00 开始，持续 1 小时
- 从“新建”按钮创建：以当前所在视图日期为准
- 状态默认为“待进行”
- 全天默认为关闭

### 14.3 表单行为

- 标题去除首尾空格后不能为空
- 分类必填
- 普通日程结束时间必须晚于开始时间
- 开启全天时切换为日期选择，结束日期默认与开始日期相同
- 结束日期早于开始日期时直接在表单内提示
- 地点和描述为可选
- 保存时按钮进入加载状态，禁止重复提交
- 接口失败时保留用户已经填写的内容
- 字段级错误显示在对应字段下方，接口级错误显示在表单顶部
- 成功保存后关闭表单、刷新当前时间范围、打开新日程详情或显示轻量成功提示

### 14.4 时间处理

- 用户输入和界面展示均使用浏览器本地时区
- 后端自动来源的“今天 09:00–22:00”排程窗口按 `APP_TIMEZONE` 计算，与浏览器时区无关
- 发起请求前转换为 UTC ISO 8601 字符串
- 查询当前日历范围时，将本地范围的开始和结束转换为 UTC
- 后端返回的 `Z` 时间转换为浏览器本地时间显示
- 编辑时不能因时区转换改变原始时间点
- 全天日程按日期字段处理，不展示本地时刻
- 后端以 UTC 日期分量表达全天日期，前端适配层应直接使用用户选择的日历日期构造 UTC 日期锚点，不能先按本地午夜换算
- 解析全天日程时按 UTC 日期分量读取开始和结束日期，再转换为 FullCalendar 的结束日期不包含规则
- 例如用户选择 11 月 5 日至 11 月 6 日，接口中的首尾日期都应被识别为 5 日和 6 日，不能显示成 4 日或 7 日

## 15. 搜索与筛选

### 15.1 搜索

- 顶部搜索框用于搜索标题和描述
- 输入后 300ms 发起查询，避免每个按键都请求
- 搜索结果按日期分组，显示分类、标题、日期和时间
- 点击结果后跳到对应日期并打开详情
- 无结果时显示“没有找到匹配的日程”
- 搜索请求失败时显示重试入口
- 清空关键词后恢复日历当前范围数据

### 15.2 筛选

- 分类支持多选
- 状态支持多选
- 时间范围筛选与当前日历视图联动
- 多个筛选条件需要同时生效
- 当前已启用筛选使用简短文字摘要，例如“工作、私人时间 · 待进行”
- 提供“清除全部”按钮
- 筛选条件下无数据时显示专门的无结果状态，并允许一键清除

## 16. 状态与反馈

### 16.1 初始加载

- 页面首次加载显示保留布局形状的骨架屏
- 日历网格和侧栏尺寸不能跳动
- 不使用覆盖整个页面的长时间旋转加载图标

### 16.2 局部加载

- 切换日期或视图时，在日历区域顶部显示细进度条或轻量遮罩
- 搜索请求在搜索框内显示加载状态
- 保存操作只在提交按钮中显示加载状态

### 16.3 空状态

- 今日无日程：“今天还没有安排” + “新建日程”
- 当前范围无日程：“这个时间段还没有安排”
- 搜索无结果：“没有找到匹配的日程”
- 筛选无结果：“没有符合筛选条件的日程” + “清除筛选”

空状态文字保持平静、直接，不使用夸张插画或连续感叹号。

### 16.4 错误反馈

- 表单校验错误显示在字段附近
- 网络或服务错误显示在操作区域顶部，并提供重试
- 删除失败保留原日程并显示错误
- 成功保存和删除使用右上角轻提示，2～3 秒自动消失
- 错误提示不能仅依赖颜色，需要同时包含图标和文字

## 17. 删除与离开确认

删除确认弹窗需要：

- 标题：“删除这个日程？”
- 正文包含日程标题和日期
- 取消按钮使用普通样式
- 删除按钮使用危险色
- 删除进行中禁止重复点击

以下场景需要离开确认：

- 表单存在未保存修改时关闭面板
- 表单存在未保存修改时切换日程
- 表单存在未保存修改时刷新或离开页面

没有修改时直接关闭，不弹出无意义提示。

## 18. 无障碍与可读性

- 分类不能只依赖颜色，必须出现文字、字符或图标
- 正文与背景的对比度满足 WCAG AA
- 所有可点击日程使用按钮语义，支持键盘 Enter 和 Space
- 键盘焦点环清晰可见，不通过 `outline: none` 移除
- 抽屉和弹窗打开后焦点进入内部，关闭后回到触发元素
- 抽屉和弹窗需要焦点限制和 `Esc` 关闭
- 图标按钮必须提供 `aria-label`
- 颜色筛选器使用可访问的复选或切换语义
- 表单错误与字段建立可访问关联
- 移动端控件触控区域不小于 44×44px
- 尊重减小动效设置

## 19. 文案规范

使用简短、自然、中性的中文：

| 场景 | 推荐文案 |
| --- | --- |
| 新建 | 新建日程 |
| 保存 | 保存 |
| 编辑 | 编辑 |
| 删除 | 删除 |
| 返回今天 | 今天 |
| 保存成功 | 日程已保存 |
| 删除成功 | 日程已删除 |
| 今日为空 | 今天还没有安排 |
| 搜索为空 | 没有找到匹配的日程 |
| 放弃修改 | 还有未保存的修改，确定关闭吗？ |

按钮文本避免使用“确定”“提交”作为主要操作名称，应直接表达结果。

## 22. 当前界面不包含

- 提醒设置和通知中心
- 重复日程设置
- 标签管理

## 23. 前端验收清单

### 23.1 视觉

- 页面整体呈现暖纸背景、墨色文字和低饱和三分类色
- 三类日程同时具备颜色和文字识别
- 日历主体没有明显卡片堆叠和厚重阴影
- 桌面布局在 1280px、1440px 和 1920px 下比例稳定
- 移动端在 320px、390px 和 430px 宽度下无横向溢出

### 23.2 功能

- 未登录时进入登录页；首次部署引导创建管理员账号，已初始化后可在登录页进入注册页创建新账号
- 手动创建日程时分类必须主动选择
- 点击空白日期或时间格能够带入对应日期和时间
- 日程创建、查看、编辑和删除完整可用
- 日、周、月视图可以正确切换
- 分类、状态、关键词和日期范围可以组合筛选
- 全天和跨天日程在正确的日期中显示
- 浏览器时区转换后时间仍然正确
- 刷新页面后可以查到已保存日程

### 23.3 状态

- 初始加载、局部加载、空数据、搜索为空、筛选为空和错误状态均有明确反馈
- 表单失败后用户输入不会丢失
- 删除前有确认，删除期间不能重复提交
- 未保存修改关闭面板时会提示

### 23.4 无障碍

- 键盘可以完成创建、打开详情、编辑和关闭弹层
- 焦点环清晰，弹层焦点不会逃逸到背景
- 分类不只通过颜色表达
- 移动端触控区域满足最小尺寸

### 23.5 范围

- 页面不出现提醒、重复、标签、第三方接入和多用户入口
- 不出现无法被当前后端 API 支持的操作
- 不提供拖拽或缩放修改时间

## 24. 设计结论

第一版采用“温暖的安静手账”视觉方向，桌面端以周视图为主，移动端以今日议程为主。整体使用暖纸色、墨色文字、细线网格和三种低饱和分类色，通过左侧小月历和分类筛选、中央日历、右侧今日议程与详情面板形成个人时间管理空间。

实现时优先保证日程的创建、查找、分类识别和状态反馈清楚，再调整装饰细节。所有视觉元素都必须服务于时间阅读，不使用与后端能力和第一版范围不匹配的功能入口。
